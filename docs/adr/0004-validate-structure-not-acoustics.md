# Validate structure, not acoustics

RVRBoTron is deliberately able to "produce the wrong answer on request" — `shuffle: false`, `delayStrategy: even`, and similar flags exist specifically because ablations are part of the research space (docs/design/reverb/stages/09-composition.md). Loop overlap (#63) is the first case where this showed up as an *emergent* interaction between two stages rather than an explicit flag: a Diffuser `totalMs` that outlasts the Feedback Loop's `delayMinMs` produces a real, audible energy buildup that reads as unpleasant past a certain amount, yet it was left unguarded — not documented as an oversight, but decided against on purpose, because no measured boundary between "fine" and "weird" exists to encode as a rule, and adding one would narrow the exact parameter space a researcher needs to explore.

This generalizes beyond Loop overlap: validation in this codebase rejects the *structurally impossible* — mismatched channel counts, non-orthogonal matrices, unstable shelf filters, orderings that violate the Composition's wiring rules — never the *acoustically unfavorable*. A configuration that renders and measures correctly is never rejected merely because it might sound bad. Future emergent interactions like this one should default to documentation over enforcement unless there's a structural, not aesthetic, reason to reject.

Damping's Reference-band accuracy (#76) is the second case of this. A one-pole shelf's transition is deliberately gentle — many octaves wide, by design (docs/design/reverb/stages/05-damping.md's "Filter choice": "Gentle slopes, minimal ringing... Steeper filters colour the tail") — which means even the documented research-baseline Damping default (`highRatio` 0.5 at `highHz` 4000, two octaves above the Reference band) leaks enough into 1 kHz to imply an RT60 more than 5% from requested `rt60Sec`, at any loop time or `rt60Sec` scale tried (a toy fixture and the documented 100-200 ms/2.4 s Reference configuration both land around 5.3-7%). This was confirmed to be the filter's real, correctly-implemented behavior rather than a coefficient bug by checking its 1 kHz magnitude three independent ways that must agree only if the math is right: the closed-form magnitude formula used in resolution, direct evaluation of H(e^{j·ω}) via a complex exponential, and a raw time-domain simulation of the actual `y[n] = b0·x[n] + b1·x[n-1] - a1·y[n-1]` recurrence driven by a sine wave and measured at steady state. All three agreed to four decimal places.

A >5% Reference-band deviation is not unsafe and not a substitution: the render is stable and does exactly what was requested, so — per this ADR's own rule — it is not rejected. `ResolvedDamping` records the actual implied 1 kHz decay (`expectedReferenceRt60Sec`) regardless of how far it lands from `rt60Sec`, so nothing about the outcome is silent; a future analysis or report layer (tail analysis #78, the Damping sweep #79) flags a deviation past 10% as significant when presenting results, but that is a reporting concern, not a validation gate. Only genuine instability (boost above a ratio of 1.0, #77) is a rejection.
